# План экспериментов: методы × контексты

## Порядок работ

Метрики → ядро матрицы → расширение → перенос. Метрики фиксируются первыми,
иначе каждый метод придётся мерить заново и появится соблазн подобрать метрику под результат.

---

## Методы (7 + адаптации)

| # | Метод | Что проверяет |
|---|---|---|
| 0 | База, без вмешательства | Точка отсчёта, замер разрыва H2 |
| 1 | Сильный промпт | Хватает ли явной инструкции; подбирается на validation |
| 2 | Явный пересказ ответа инструмента перед действием | Помогает ли просто «выписать» наблюдение |
| 3 | Явное ведение состояния (OODA-подобный контроллер) | **Главный конкурент.** Решает ли проблему проще и дешевле |
| 4 | LoRA/SFT на **тех же** данных | Потолок по качеству; честно только при одинаковых данных |
| 5 | Простой steering (contrastive activation addition) | Базовая версия метода |
| 6 | Steering с гейтом по префиксу и наблюдению | Если фиксированное вмешательство вредит инвариантным парам |

Адаптации для сравнения: **TACT** (общий контур), **PRISMS** (на релевантном срезе ошибок вызова).
Где исходный метод нельзя честно воспроизвести — называть адаптацией и указывать различия.

Диагностический ориентир (не baseline): верхняя граница с oracle-выбором следующего действия.

**Правила честности.**
- Один и тот же scaffold для всех методов.
- Одинаковые данные для всех обучаемых методов, иначе результат не про способ вмешательства.
- Гейт не использует oracle-метку, контрфактическую ветку и будущую траекторию.
- Веса базовой модели не меняются в основной версии метода.

## Поэтапный план (полный факторный не делать — взорвётся)

### Этап 1. Ядро
Методы × тип пары. Одна модель, один домен, 100–200 парных задач.
→ Основная таблица результатов. Здесь же проверяются H1, H2, H3.

### Этап 2. Расширение
Добавить **только** те оси, где на ядре видна разница. Если явность условия
не влияет — не тратить прогоны.

### Этап 3. Перенос
Вторая модель и новое семейство инструментов, **без подбора по test**.
Для второй модели переносится **алгоритм поиска вектора и выбора гиперпараметров**,
а не координаты вектора между несовместимыми hidden spaces.

### Этап 4. Внешняя проверка
ToolRobustBench как одношаговый диагностический срез (после аудита кода и лицензии).
Одна открытая многошаговая среда с исполняемым оценщиком.
Если внешняя среда не даёт строго парных миров — результаты сообщать отдельно.

## Окружение (зафиксировать до первого прогона)

Открытая модель 3–8B с доступом к residual stream (меньшие ошибаются чаще → больше материала).
Локальный детерминированный stateful-симулятор с программным evaluator.

Зафиксировать и записать в репо: checkpoint · chat template · формат tool message ·
параметры генерации · seed · версия evaluator.

Задачи должны требовать нескольких вызовов и содержать как минимум один результат,
влияющий на оптимальный план. Менять только состояние мира и результат контролируемого
вызова, сохраняя исходный запрос, набор инструментов и бюджет.

Держать скрытый набор сценариев, написанных отдельно от train-шаблонов.
На стратифицированной подвыборке вручную проверить согласованность миров
и множества допустимых действий.

## Шаги метода (steering)

1. **Воспроизвести ошибку.** Разделить ошибки по стадиям: до вызова / чтение результата /
   планирование следующего шага / исполнение. Метод направлен **только** на средний переход.
2. **Локализовать кандидатов.** Собрать на train сопоставимые правильные и ошибочные
   траектории после ответов инструмента. Сравнить активации в трёх окнах:
   чтение существенного поля · сразу после сообщения · перед первым токеном действия.
3. **Проверить причинность.** Добавление/подавление направления, patching согласованных пар,
   полный список контролей из HYPOTHESES.md (H3).
4. **Вмешиваться только после результата.** Начать с фиксированного `h′ₗ = hₗ + αvₗ`.
   Слой, `α`, окно и правило включения выбирать **только на validation**.
5. **Отделить представление от вычислений.** Проверить, не вызван ли эффект удлинением
   рассуждения, другими вызовами инструментов или изменением формата вывода.
   Dose–response по коэффициенту, повтор на независимых задачах.
